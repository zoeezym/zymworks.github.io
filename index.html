平台从 0 到 1，我盯四个环节

  • 定义。先划清能力边界：哪些交给模型、哪些交给规则、哪些必须留人工兜底，写进 PRD 再排期。模型答不了的问题，交互上要给出下一步动作。
  • 设计。把能力做成可复用资源：技能、MCP、HTTP 接口、知识库按任务组合，一套资源配置支撑多个省份的交付。
  • 落地。到项目里配场景：省公司的差异用配置和场景包解决，避免每省改一版代码，交付周期才跟得上。
  • 验证。效果要有口径：评测集、评估器、人工校准配齐，版本之间才敢说变好了；没有基线的提升数字，不上汇报。

01 平台型 · 0→1 到 1→N

数字员工平台 AgentOS

主导 0→1 与 V2 升级 · 2024.10 起参与，2025.08 转产品

企业需求从"知识问答"走到"任务执行"，平台要把能力配置、任务执行、结果交付和管理放进同一条流程里。

  • 任务执行体验：普通模式与计划模式的入口、阶段状态、工具调用与结果呈现；长任务支持后台执行、断线回看。
  • 能力组合：技能、MCP、HTTP 接口、知识库、协作 Agent 的配置关系，把场景能力沉淀成可复用资源。
  • 版本治理：草稿、待审核候选版本、正式版本三级，配合依赖资源版本绑定与多租户角色权限。
  • 多形态交付：统一开发平台、Web 对话页、Copilot 侧边栏、开放 API、场景化工作台，按客户接入方式组合。

落地：10+ 省份本地化部署，1 万+ 人使用。

公开材料：内部系统，暂不公开

02 平台型 · 知识能力组件

智能知识库

深度参与产品设计 · 企业知识加工与 RAG 问答

企业文档分散、结构复杂、检索结果难判断，需要一条从接入、加工到检索验证的完整流程，给数字员工提供可复用的知识能力。

  • 知识加工：上传、解析、清洗、分段、向量化的流程与异步状态反馈，处理表格、图片与正文的关联。
  • 混合检索：关键词与向量互补，结果融合加重排序，支持检索测试与参数调整。
  • 知识运营：知识库、文档、片段三级管理，让管理员能判断问题出在知识缺失、分段还是检索策略。
  • 质量验证：参考问答加检索上下文的 RAG 评测，分别看上下文精确度、召回、相关性、忠实度与幻觉。

结果：知识能力作为平台标准组件被多个省公司项目复用（客户侧数据待确认）。

公开材料：内部系统，暂不公开

03 工具型 · 0→1

Agent 评测平台

深度参与 0→1 设计与落地 · 评测与观测

Agent、RAG 与多轮对话的效果难比较、问题难归因，需要一个地方把数据集、评估器、评测任务和结果分析管起来。

  • 数据体系：单轮问答、RAG、Agent、多轮对话四类数据集结构，区分参考答案、参考上下文、预期工具与任务目标。
  • 任务配置：数据集与版本 → 应用 → 字段映射 → 组合评估器的四步创建流程。
  • 评价框架：内容质量、知识依据、工具调用、任务结果四个维度，评分与判定理由可下钻到失败样本。
  • 判官可信度：判官模型自配置与推荐，人工金标校准、A/B 顺序交换复判、冲突样本复核。

产出：可演示的交互原型，加上评测数据集结构与评估器方案。
