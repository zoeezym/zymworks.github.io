1. 与 v1.0 的差异说明

v1.0 已经把产品定位、五模块、四级评估、消融实验讲清楚了，这是这个项目最扎实的部分。缺的是"能不能卖给企业"这一层：企业采购第一轮问的永远是权限、数据隔离、审计、成本、变更管理，这四项 v1.0 一项没写。

本文件补的就是这四项，以及被 v1.0 省略的角色分工与后台。

2. 角色与权限

2.1 角色定义

数据分析支撑授权数据域问数、校验、代业务提问否是
数据管理员授权数据源接入数据源、字段语义映射否是

2.3 三条硬规则

  1. 业务用户默认看不到原始 SQL。 SQL 是给分析支撑与管理员做校验用的，对业务用户暴露只会制造困惑。可在租户级配置放开。
  2. 改口径与批口径不能是同一个人。 指标管理员提交评审，质量负责人批准。单人租户无法满足时，系统强制记录"单人模式"并在看板标注。
  3. 权限变更即时生效，且必须留痕。 撤回权限后，该用户正在进行的会话立即失效。

3. 租户与数据隔离

3.1 部署形态

形态隔离方式适用差异点
SaaS 多租户tenant_id 逻辑隔离，所有表带租户字段，查询层强制注入中小企业共享模型调用，配额按租户计
私有化单租户独立部署，物理隔离金融、运营商可接本地 Ollama，数据不出内网
混合元数据在 SaaS，数据源在内网，通过代理只回传查询结果数据敏感但想用 SaaS 运维需评估代理链路的合规性

待确认：目标客户以哪类为主。这决定 tenant_id 是否要贯穿到指标字典与评估集。

3.2 隔离层级

层级规则越界表现
租户数据源、指标字典、评估集、日志全部按租户隔离不可见、不可查、接口返回 404 而非 403（避免探测）
数据源用户只能对自己被授权的数据源问数问句涉及未授权表时，明确回答"你没有该数据域的权限"，不做部分回答
行级（RLS）按用户属性自动注入过滤条件，如 region in ('华东')注入失败则拒绝执行，不允许漏掉过滤条件
列级敏感字段（手机号、证件号、精确地址）对业务用户掩码掩码在结果集生成后做，SQL 层不返回明文
指标级指标可设置可见业务域无权限的指标不出现在澄清候选中

3.3 行级权限的实现约束

行级权限不能靠提示词约束模型，必须由查询执行层强制注入。原因：模型可能生成不带过滤条件的 SQL，靠提示词约束不可靠。

实现要求：

  • 用户属性表（部门、区域、客户等级）与数据源的表字段有映射关系。
  • 生成 SQL 后，执行前由中间层解析 SQL 的 FROM/WHERE，强制追加过滤条件；解析失败则拒绝执行。
  • 每次强制注入都记录日志：注入的字段、值、原始 SQL、最终 SQL。

4. 指标治理生命周期

4.1 状态机

草稿 ──提交──> 待评审 ──批准──> 已发布 ──归档──> 已归档
  ↑              │                 │
  └──驳回────────┘                 └──变更──> 草稿（新版本）
状态可编辑可被问答引用操作人准入条件
草稿是否指标管理员名称、口径、公式、时间口径四项必填
待评审否否—需至少 1 名评审人
已发布否（需走变更）是质量负责人评审通过 + 至少 1 条验证用例
已归档否否质量负责人无活跃引用，或有替代指标

4.2 变更管控

变更类型例子是否需要评审是否影响历史答案
描述修正口径说明文字改清楚，公式不变否（记录即可）否
同义词扩充新增"营收额"映射到实付收入否否
公式变更实付收入改为含退款冲减是是，历史答案需标注"口径已变更"
时间口径变更自然月改为账期月是是
维度变更新增按渠道拆分是否

4.3 变更影响分析

公式或时间口径变更时，系统必须先输出影响面，才能提交评审：

输出项内容
受影响问句近 90 天引用该指标的问答条数与 Top 10 问句
受影响报告已导出或已保存的报告中引用该指标的清单
数值差异预估用新旧两种口径对近 3 个月数据各算一次，给出差异幅度
通知对象引用过该指标的用户清单，支持一键站内通知

没有影响分析的变更不允许提交评审。这条规则来自一个常见事故：口径改了，没人通知，业务拿着两套数字对不上，最后整个产品的可信度崩掉。

4.4 语义层版本化

  • 每次发布生成一个语义层版本号（如 sem-20261027-03）。
  • 版本支持并存：v_prev 与 v_cur 同时可用，切换按租户或按用户灰度。
  • 任一答案的记录里带上生成时使用的语义层版本，事后可复现。
  • 版本回滚：一键切回上一版，影响时间为下一次查询生效。

6. 状态机与异常分支

6.1 一次问数的状态流转

接收问句
  → 权限预检（数据域、指标可见性）
    → 口径识别（命中字典？有歧义？）
      → 澄清（最多 2 轮）
        → SQL 生成（含语义层注入）
          → 安全校验（只读、白名单表、扫描行数上限）
            → 执行
              → 双通道验证
                → 结果渲染（图表 + 口径回显 + 置信度）
                  → 用户动作（追问 / 导出 / 反馈 / 转人工）

每个节点的失败分支：

节点失败行为
权限预检无权限拒绝并说明缺哪个数据域，不生成 SQL
口径识别无匹配指标用裸 schema 生成，但答案顶部标注"未匹配到已定义口径"
澄清2 轮未收敛按默认口径生成，并在答案顶部标注"已按默认口径 X，可能与你的预期不同"
澄清用户主动跳过同上，且记录跳过行为用于优化
SQL 生成生成失败重试 1 次，仍失败则返回"无法生成"，附缺失信息说明
安全校验命中拦截拒绝执行，返回拦截原因（见 03 文档 §3）
执行超时30s 中断，返回"查询超时，建议缩小时间范围或加筛选条件"
执行空结果区分三类：条件写错 / 真的没有数据 / 权限导致为空。前两类给出不同提示
双通道不一致降级为"建议人工核对"，并展示两条 SQL 与两组结果的差异点
渲染结果超行数上限只展示前 1000 行，提示"已截断，导出可取全量（需导出权限）"

6.2 会话状态

状态保持时间说明
活跃会话30 分钟无操作转休眠上下文（含已确认口径）保留
休眠会话7 天可恢复，恢复时提示"口径可能已变更"
归档90 天只读，可导出
删除按租户配置需用户主动，删除后审计日志仍保留元信息

7. AI 能力边界与输出约束

7.1 可以做的

  • 解析中文问句为结构化查询意图（指标、维度、时间、过滤、排序、对比方式）
  • 从语义层检索相关口径、同义词、历史 SQL 样例，注入生成上下文
  • 生成只读 SQL
  • 生成结论文案（基于查询结果，不得引入结果外的信息）
  • 解释口径与 SQL 逻辑
  • 生成图表建议（柱/线/占比/表格）

7.2 不可以做的

禁止项原因拦截位置
生成任何写操作 SQL数据安全语法解析层，关键词白名单
查询白名单外的表数据边界表名提取后比对白名单
跨租户查询隔离SQL 中强制带 tenant_id，模型无需也不被允许处理
绕过行级权限合规执行层强制注入，不依赖模型
编造数字可信度结论文案只能引用结果集中的数值，渲染层校验数字是否出现在结果里
引用未发布指标的口径治理检索只返回已发布指标
返回超过上限的行数成本执行层 LIMIT，超限截断并提示
输出原始 SQL 给无权限用户信息泄露渲染层按权限隐藏
对结果做因果判断（"因为 X 所以 Y"）越界提示词约束 + 输出层检测因果连词，改为"数据显示 X 与 Y 同时变化"

7.3 结论生成的硬约束

结论文案必须满足三条，否则降级为纯数据展示：

  1. 每个数字都能在结果集中找到对应值（渲染时校验）。
  2. 环比/同比必须写明对比区间与口径。
  3. 不使用"显著""大幅"这类无阈值的程度词，除非配置了阈值（如环比 > 5% 才可说"下降"）。

8. 成本与容量控制

控制项默认值可配置范围说明
单次查询扫描行数上限500 万行（待确认）10 万–5000 万超限拒绝执行并提示加筛选
单次返回行数上限1000 行100–10000超限截断
单用户每日查询次数200 次20–2000按角色分档
单租户每日查询次数待确认—防单租户占满资源
查询超时30s10–120s超时中断
双通道验证触发率100%（关键问句）可降为抽样 20%关键问句定义见下
结果缓存相同问句 + 相同语义层版本，24 小时—命中缓存不消耗模型调用
模型降级小模型先行，失败升级大模型—简单问句用小模型

关键问句定义（触发双通道验证）：涉及收入/成本类指标、涉及跨表 join、涉及时间边界计算、用户主动点击"这个数准吗"。

成本估算方法（面试可讲）：单次问数成本 = 语义层检索 token + 生成 token + 双通道二次生成 token。按每次约 3000 input + 800 output token 估算，日均 1000 次问数的租户，月成本量级在数百元（待确认具体模型单价）。这个数字要能算出来，否则无法回答"这东西贵不贵"。

10. 验收标准（v0.2 新增）

#场景Given / When / Then
1行级权限用户属性为"华东"，问"全国收入"，则 SQL 被强制注入华东过滤，答案标注"已按你的数据范围过滤"
2权限拒绝用户无财务域权限，问"成本"，则拒绝并说明缺哪个域，不生成 SQL
3指标未发布某指标处于待评审，问句命中其同义词，则不走该口径，答案标注"未匹配到已发布口径"
4口径变更修改实付收入公式并发布，则历史答案详情页显示"该答案生成于口径 v1，当前为 v2"
5影响分析提交公式变更评审时未填写影响分析，则系统拒绝提交
6语义层回滚发布 v2 后发现问题，回滚到 v1，则下一次查询使用 v1 并记录版本
7空结果区分查询区间内确无数据，则提示"该区间无数据"；条件写错（如时间格式），则提示"条件可能有误"并给出建议
8超时查询超 30s，则中断并提示缩小范围，不返回部分结果
9截断结果 5 万行，则只返回前 1000 行并提示已截断，导出需权限
10双通道不一致两条 SQL 结果差异 > 1%，则答案降级为"建议人工核对"，展示差异点
11数字校验结论文案里的数字未出现在结果集中，则降级为纯数据展示并告警
12SQL 隐藏业务用户点击"查看 SQL"，则不展示内容，提示"需要分析权限"
13配额用户当日第 201 次查询，则拒绝并提示配额已用尽，可申请临时提升
14缓存同一用户 24 小时内问同一问句，则命中缓存，响应 < 1s，且标注"缓存结果"
15审计审计员可按用户查出：问了什么、生成了什么 SQL、返回多少行、耗时多少
